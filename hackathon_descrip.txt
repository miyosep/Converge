GWDC Korea Hackathon: FuriosaAI X Bricksum ·Agent Finance Bonus Track Challenge Brief
Challenge A: Build a Financial Service Powered by AI Agents and Blockchain
Build a financial service prototype in which an AI agent helps users complete a purchase, payment, or asset management task, prevents spending outside the user's instructions, or helps investigate a transaction dispute. Use the NPU-based Kiln API, an LLM token API, to power the agent and integrate blockchain into the selected workflow. Kiln provides access to low-power NPU inference, enabling teams to explore how efficiently a complete service can operate in terms of token usage and energy consumption. Connect the user's request and relevant inputs, such as a budget, permitted items or merchants, and a deadline, to actions and records that can be inspected. Possible implementations include a purchasing agent that respects user conditions, a wallet interface for approving and stopping agent spending, buyer and seller agents that negotiate and settle a transaction, or a tool that explains purchases using approval and transaction records. Teams may focus on one function, combine several, or propose another idea within agent finance.
Acceptance Criteria
User Need & Workflow: Identify the intended user and the problem being solved. Demonstrate the selected workflow from user input to a usable outcome, and explain which task the AI agent performs and which parts you kept in code.
Kiln API Integration & Efficiency: The resulting AI agent must operate using the NPU-based Kiln API with gpt-oss-120b. Demonstrate actual API calls within the selected workflow and show how the responses inform the agent's decisions or actions. Report token usage broken down by flow rather than as a single total, and explain how the design reduces unnecessary inference and energy consumption, supporting energy estimates with available measurements or clearly stated assumptions.
Blockchain Integration: Demonstrate the selected functionality on a devnet or testnet. An end-to-end run of the workflow should produce at least one on-chain transaction — a payment, a settlement, or a record written on-chain — and provide its transaction hash with the matching log or history entry. Show how the chain is used by the workflow: which state the agent reads, writes, or settles.
Selected Function: Declare in one sentence, in your README, the function you built — a purchasing agent, a wallet and approval tool, negotiating buyer and seller agents, an evidence and dispute tool, or another function within agent finance. The work is evaluated against the function you declared rather than a fixed list of expected features.
Condition Checks & Evidence: Repeat the end-to-end run twice with the user's conditions changed — for example a reduced budget, or a merchant that is no longer permitted — and verify the behavior through logs or history. Spending controls should stop actions outside the permitted scope. Evidence or dispute tools should let another person inspect the records and assess whether the transaction followed the user's conditions.
